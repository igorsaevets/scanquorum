## What the tool claims to be

Scanned PDFs contain a text layer produced by some OCR program, often decades ago. Search
tools read it, AI assistants quote it, and nobody verifies it against the page. ScanQuorum
reads the page with several independent OCR engines and accepts a word only when at least two
agree; where they disagree it refuses to decide and shows the reader a cropped image.

The load-bearing claim: **no language model participates in transcription, and this is enforced
by code rather than by a prompt.**

## Answer these six, in order, and be specific

**Q1. Is the central claim true?**
Trace every path by which a character could enter the output. Is there any route by which text
not proposed by an OCR engine reaches the `.md` file or the accepted output? `verify_ai.py`
lets a vision model take part — read `_parse_choice` and decide whether the boundary is real or
whether I have merely made it inconvenient to cross. If you find a hole, name the file and
line.

**Q2. The tie-break fix — is it right, and did I miss a site?**
Four places in the cascade resolved a tie via `Counter.most_common()` or `max()`, both of which
return whichever item a dict yielded first. Measured: 165 of 11,780 distinct decisions (1.40 %)
changed answer when the engines were reordered; 29 changed a digit. Three of the four sites now
fall through to a dispute or use a stated rule; one (`pick_form`) uses "fewest stray marks,
then shortest, then lexicographic" among forms that share a normalised key.

Is `pick_form`'s choice defensible, or is it an arbitrary rule wearing a justification? **Is
there a fifth site I have not found?** Check `decide()` line by line for any other ordering
dependence, including in `align()` and in the `by_sk` grouping.

**Q3. Are the statistical claims honest?**
The README reports 98.65 % → 99.15 % (Horvitz–Thompson, 56 crops) and states plainly that the
improvement is **not significant** (exact McNemar, 4 discordant pairs, p = 0.125). It also
states that the reference standard **cannot see truncation by construction**, because both the
tool and the measurement inherit the same possibly-wrong box, and that 7 of 7 observed errors
were truncations.

Is anything overstated? Is anything understated? Specifically: is it legitimate to publish a
99.15 % figure at all when the largest known error class is invisible to the estimator that
produced it? Argue either way, but commit to an answer.

**Q4. What breaks first for a stranger?**
Someone clones this tomorrow on macOS or Linux with no Tesseract and no GPU. What fails, and
does the failure explain itself? Note that engine adapters raise `ImportError` when the engine
is absent and the pipeline reports "engine NOT available" and warns that fewer than three
voters is not a quorum. Is that handling honest, or does the tool still produce output that
looks authoritative?

**Q5. Prior art — search the web, do not answer from memory.**
The README claims that multi-engine OCR voting is old (ROVER, Fiscus 1997) but that this
combination was not found: voting whose *refusals* are a first-class output, unresolved places
rendered as images for a human, and an architectural bar on LLM transcription.
**Find a project that does this combination.** If one exists the README must cite it. Give URLs
with dates. "I could not find one" is an acceptable answer only if you say what you searched.

**Q6. The commercial and audience question.**
The stated audience is legal departments, finance/audit/compliance, founders, and people
building RAG over scanned documents. Does the README speak to them, or to engineers? Name the
single sentence that would most improve adoption, and the single claim most likely to be
attacked by a hostile reader.

  18| 
  19| ## Why this exists
  20| 
  21| A page of a 1974 immigration decision has this in its text layer:
  22| 
  23| ```
  24| Decided by Regional Commissioner May 1, .1974
  25| ```
  26| 
  27| That stray full stop was put there by an OCR program in the year 2000 and has been sitting in
  28| the file ever since. It is harmless. Four lines away, in the same class of document, the
  29| citation `12-855` had been recorded as `12369`.
  30| 
  31| That one is not harmless. It is a pointer to a different decision — and it looks exactly as
  32| authoritative as the correct one, because a text layer carries no confidence, no provenance
  33| and no warning. It is just text.
  34| 
  35| Now put a modern AI in front of that file. Ask it to quote the decision. It will quote it
  36| perfectly — perfectly reproducing the wrong citation, and adding a fluent explanation of what
  37| that decision held. Every hallucination check you run will pass, because the model did not
  38| hallucinate. It read what was in the file.
  39| 
  40| > **The document was corrupted twenty-five years before the AI ever saw it.**
  41| 
  42| That is the failure this tool exists to catch, and it is invisible to every tool that checks
  43| whether an AI made something up.

  47| ## What it actually does
  48| 
  49| **1. Reads the page several times, independently.** Four engines by default: the text layer
  50| already in your PDF, two neural OCR models, and a classical one. They fail differently, which
  51| is the entire reason to run more than one.

  53| **2. Accepts a word only on a quorum.** A word enters the output when at least two independent
  54| engines read it the same way. On a 41-page government index: **86.55 % of 29,853 words** were

  57| **3. Refuses to guess the rest.** **1.18 % — 353 words** — could not be reconciled. Those are
  58| not silently filled in with a best guess. They are listed, with page and coordinates, and the
  59| tool will render each one as a cropped image so a person can look at it in three seconds.
  60| 
  61| **4. Never invents a character.** Every rule in the decision engine returns a candidate that
  62| some engine actually proposed, or nothing. There is no code path that composes text. This is
  63| the property that makes the output safe to paste into a filing, and it is verified by a test
  64| you can run yourself.
  65| 
  66| **5. Writes a Markdown file next to the PDF.** Because your search tool cannot read a PDF and
  67| never told you, and because an AI given a `.md` file with a provenance header behaves very
  68| differently from one handed a PDF.

 195| ## What it does not do, said plainly
 196| 
 197| - **It does not tell you the truth about the page.** It tells you where independent engines
 198|   agree. Engines can agree and be wrong together — most often when the word is inside a box
 199|   that was cut off before any of them saw it. Measured on this corpus: of 24 disagreements
 200|   checked by eye, the tool was right on 17 and wrong on 7, and **all 7 were truncations**. A
 201|   crop-relative reference standard cannot see that class by construction, so the headline
 202|   accuracy above does not cover it.
 203| - **It is not a reader for handwriting, tables or forms.** It votes on words in running text.
 204| - **It does not know what your document means.** It answers one question: which words on this
 205|   page can be relied on.
 206| - **Four engines are not four independent opinions.** Two of the default engines share a text
 207|   detector — 2,921 of 3,006 boxes identical — so "four voices" is nearer three. This is why the
 208|   fourth engine helped at all: it was added for independence, not for strength, and it is the
 209|   weakest of the four.
 210| - **A flag can mean the tool is wrong.** Before correcting a document because ScanQuorum
 211|   flagged it, look at the crop. That is why the crop is produced.

## `scanquorum/vote.py`  (295 lines)

```
   1| # scanquorum/vote.py  v1.0
   2| #
   3| # THE DECISION ENGINE. Given what several independent OCR engines read at the same
   4| # place on the page, decide what to accept -- or refuse to decide and say so.
   5| #
   6| # ONE INVARIANT GOVERNS EVERY RULE BELOW:
   7| #
   8| #     No rule may return a string that no engine proposed.
   9| #
  10| # Every branch returns either a candidate verbatim, or a normalised form of a
  11| # candidate, or None. Nothing here composes characters, "corrects spelling",
  12| # or asks a language model. That is the entire reason this file can be trusted
  13| # with a legal quotation: the worst it can do is pick the wrong engine's answer,
  14| # which is a visible error, not an invented one.
  15| #
  16| # The cascade is ordered by how much evidence each rule requires, most first.
  17| # A rule only runs when every rule above it has declined.
  18| #
  19| # PARITY: tests/test_vote_parity.py replays 29,853 real decisions recorded from
  20| # the measured run and asserts this file reproduces every one of them. If you
  21| # change anything here and that test still passes, you changed nothing that
  22| # matters; if it fails, you changed the measured behaviour and the numbers in
  23| # README.md no longer describe this code.
  24| import re
  25| import difflib
  26| import unicodedata
  27| import collections
  28| 
  29| VERSION = "1.0"
  30| 
  31| # Characters that different engines emit for "a dash". A citation printed as
  32| # 12-855 comes back as 12‑855, 12–855 or 12—855 depending on the engine, and
  33| # three spellings of the same dash look like three disagreeing engines.
  34| DASHES = "‐‑‒–—―−­⁃·•‧・－"
  35| TBL = {ord(c): "-" for c in DASHES}
  36| STRIP = ".,;:()[]{}'\"`«»"
  37| 
  38| # Letter/digit confusions that every OCR engine makes, because the glyphs are
  39| # genuinely ambiguous at 300 dpi in a 1970s typewriter face.
  40| CONF = {"l": "1", "I": "1", "|": "1", "i": "1", "O": "0", "o": "0", "D": "0",
  41|         "S": "5", "s": "5", "B": "8", "Z": "2", "z": "2", "G": "6", "T": "7",
  42|         "q": "9", "g": "9", "A": "4", "J": "1", "b": "6"}
  43| 
  44| CIT = re.compile(r"^\d{1,2}-\d{2,4}$")          # 12-855   volume-page citation
  45| STAT = re.compile(r"^\d{2,3}(\([a-zA-Z0-9]{1,3}\))+$")   # 245(a)(1)  statute subsection
  46| 
  47| 
  48| def norm(t):
  49|     return unicodedata.normalize("NFKC", str(t)).translate(TBL)
  50| 
  51| 
  52| def collapse(t):
  53|     """Squeeze runs of the same non-alphanumeric: '3--172' and '3—172' are one token."""
  54|     return re.sub(r"([^A-Za-z0-9])\1+", r"\1", norm(t))
  55| 
  56| 
  57| def key(tok):
  58|     return collapse(tok).strip(STRIP).lower()
  59| 
  60| 
  61| def skel(tok):
  62|     """Only the letters and digits -- '11-911' and '11911' share a skeleton."""
  63|     return re.sub(r"[^A-Za-z0-9]", "", norm(tok)).lower()
  64| 
  65| 
  66| def digitish(t):
  67|     return "".join(CONF.get(c, c) for c in collapse(t))
  68| 
  69| 
  70| def ndig(t):
  71|     return sum(c.isdigit() for c in str(t))
  72| 
  73| 
  74| def noise(tok):
  75|     return len(re.findall(r"[^A-Za-z0-9]", norm(tok)))
  76| 
  77| 
  78| def has_sep(tok):
  79|     return bool(re.search(r"[A-Za-z0-9][^A-Za-z0-9]+[A-Za-z0-9]", norm(tok)))
  80| 
  81| 
  82| def lev(a, b):
  83|     """Levenshtein distance. Used only to pick the most central candidate."""
  84|     if a == b:
  85|         return 0
  86|     prev = list(range(len(b) + 1))
  87|     for i, ca in enumerate(a, 1):
  88|         cur = [i]
  89|         for j, cb in enumerate(b, 1):
  90|             cur.append(min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + (ca != cb)))
  91|         prev = cur
  92|     return prev[-1]
  93| 
  94| 
  95| def pick_form(forms):
  96|     """Choose among surface forms that are ALREADY KNOWN to be the same word.
  97| 
  98|     🔴 TIE-BREAK, SITE 1 of 3. This replaces `Counter(forms).most_common(1)`,
  99|     which breaks a tie by INSERTION ORDER -- that is, by the order the engines
 100|     happen to sit in a Python dict. Measured on 11,780 real candidate sets:
 101|     165 of them (1.40 %) changed their answer when the engines were reordered,
 102|     and 29 of those changed a DIGIT -- '12-869' against '12369', '1910' against
 103|     '1940'. In a citation index that is a different citation.
 104| 
 105|     The same defect had already been found and fixed one branch below, for the
 106|     2:2 vote split, with the note that insertion order decides "silently, and by
 107|     an accident of dict ordering". It was fixed in one place out of four.
 108| 
 109|     Here the tie is NOT substantive: every form has the same `key()`, so they
 110|     differ only in punctuation that `key()` strips. Flagging 'sec' against
 111|     'sec.' would bury the reader in noise. So this one is settled by a stated,
 112|     deterministic rule instead of by luck: fewest stray marks, then shortest,
 113|     then lexicographic. The other two sites hold genuinely different digits and
 114|     are sent to the reader instead.
 115| 
 116|     🔴 THE FIRST VERSION OF THIS FUNCTION WAS WRONG, and the parity test caught
 117|     it on its first run. It applied the tie-break to ALL the forms and ignored
 118|     how many engines backed each one -- so with 'children;' from three engines
 119|     and 'children:' from one it returned the SINGLE engine's reading, because
 120|     ':' sorts before ';'. Three engines agreeing is not a tie. Count first;
 121|     break only the tie that is actually there.
 122|     """
 123|     c = collections.Counter(forms)
 124|     best = max(c.values())
 125|     tied = [f for f in c if c[f] == best]
 126|     return min(tied, key=lambda f: (noise(f), len(f), f))
 127| 
 128| 
 129| def align(pivot, other):
 130|     """Line up one engine's tokens against another's, so the same word on the page
 131|     is compared with the same word, not with its neighbour. Where the alignment is
 132|     ambiguous the candidate is dropped rather than guessed -- a mis-aligned
 133|     comparison manufactures disagreement, and disagreement costs a human's time."""
 134|     kp, ko = [key(t) for t in pivot], [key(t) for t in other]
 135|     sm = difflib.SequenceMatcher(None, kp, ko, autojunk=False)
 136|     m = {}
 137|     for op, i1, i2, j1, j2 in sm.get_opcodes():
 138|         if op == "equal" or (op == "replace" and (i2 - i1) == (j2 - j1)):
 139|             for d in range(i2 - i1):
 140|                 m[i1 + d] = [other[j1 + d]]
 141|         elif op == "replace":
 142|             for d in range(i1, i2):
 143|                 m[d] = other[j1:j2]
 144|         elif op == "delete":
 145|             for d in range(i1, i2):
 146|                 m.setdefault(d, [])
 147|     return m
 148| 
 149| 
 150| def decide(cands, lexicon):
 151|     """Return (chosen, rule, who).
 152| 
 153|     `cands` maps engine name -> what that engine read here, or None if it read
 154|     nothing. `chosen` is None only when the engines cannot be reconciled, and
 155|     that is a result, not a failure: it is the tool telling you which words a
 156|     person still has to look at.
 157|     """
 158|     have = [(s, v) for s, v in cands.items() if v is not None and str(v).strip()]
 159|     if not have:
 160|         return None, "EMPTY", ""
 161|     if len(have) == 1:
 162|         return norm(have[0][1]), "ONLY_ONE", have[0][0]
 163| 
 164|     # ---- 2. SEP: same digits, disagreement is only about the separator --------

   2| #
   3| # Where things are on the page. Three jobs, all geometric, none of them about
   4| # characters: find the column gutter, decide which OCR line owns each word, and
   5| # look a word up by its box quickly.
   6| import collections

   9| def iou(a, b):
  10|     x0, y0 = max(a[0], b[0]), max(a[1], b[1])
  11|     x1, y1 = min(a[2], b[2]), min(a[3], b[3])
  12|     if x1 <= x0 or y1 <= y0:
  13|         return 0.0
  14|     i = (x1 - x0) * (y1 - y0)
  15|     ua = (a[2] - a[0]) * (a[3] - a[1]) + (b[2] - b[0]) * (b[3] - b[1]) - i
  16|     return i / ua if ua > 0 else 0.0
  17| 
  18| 
  19| def gutter(boxes, page_w):
  20|     """Find the vertical whitespace channel of a two-column page, or None.
  21| 
  22|     🔴 HEURISTIC, and the tool's weakest part. It looks for a band between 30 %
  23|     and 70 % of the width that almost no box crosses. It is right on the corpus
  24|     this was measured on and is guaranteed nowhere else. Reading order is not
  25|     otherwise checked, so a wrong answer here produces text that is perfectly
  26|     recognised and in the wrong order -- a quotation that is verbatim and
  27|     meaningless. See testing/TO-TEST.md#g6."""
  28|     if len(boxes) < 10:
  29|         return None
  30|     occ = [0] * 100
  31|     for b in boxes:
  32|         for i in range(max(0, int(b[0] / page_w * 100)), min(99, int(b[2] / page_w * 100)) + 1):
  33|             occ[i] += 1
  34|     thr = max(1, int(0.02 * len(boxes)))
  35|     best, i = None, 30
  36|     while i <= 70:
  37|         if occ[i] <= thr:
  38|             j = i
  39|             while j <= 70 and occ[j] <= thr:
  40|                 j += 1
  41|             if best is None or (j - i) > (best[1] - best[0]):
  42|                 best = (i, j)
  43|             i = j
  44|         else:
  45|             i += 1
  46|     return (best[0] + best[1]) / 2 / 100 * page_w if best and (best[1] - best[0]) >= 3 else None
  47| 
  48| 
  49| def assign(ocr_lines, words):
  50|     """Map each word of the existing text layer to EXACTLY ONE OCR line.
  51| 
  52|     🔴 THE DEFECT THIS FUNCTION EXISTS TO CLOSE. The obvious loop -- for each OCR
  53|     line, take every word whose centre falls inside it -- emits a word once per
  54|     line that covers it. OCR line boxes overlap constantly on full-width pages, so
  55|     the assembled text came out as 'On On On November November November', inflating
  56|     one document by 1.29x and 4,801 surplus tokens.
  57| 
  58|     It was nearly invisible on narrow-column pages (7 cases in 29,858), which is
  59|     why it survived two rounds of code review and died the first time anyone used
  60|     the output to pull a real quotation.
  61| 
  62|     Resolution: the word belongs to the line whose vertical centre is nearest; ties
  63|     go to the tighter box. Stable under nested and slightly shifted detections."""
  64|     owner = collections.defaultdict(list)
  65|     for wi, w in enumerate(words):
  66|         cx, cy = (w[0] + w[2]) / 2, (w[1] + w[3]) / 2
  67|         best, bi = None, -1
  68|         for i, eb in enumerate(ocr_lines):
  69|             r = eb["b"]
  70|             if not (r[0] - 2 <= cx <= r[2] + 2 and r[1] - 2 <= cy <= r[3] + 2):
  71|                 continue
  72|             sc = (abs(cy - (r[1] + r[3]) / 2), (r[2] - r[0]) * (r[3] - r[1]))
  73|             if best is None or sc < best:
  74|                 best, bi = sc, i

  76|             owner[bi].append(wi)

  80| class BoxIndex:

  82|     scan is ~730 words x ~750 boxes x 200 pages = 100 million overlap tests."""
  83| 
  84|     def __init__(self, boxes, bucket=6.0):
  85|         self.bucket = bucket
  86|         self.idx = collections.defaultdict(list)
  87|         for bx in boxes or ():
  88|             for k in range(int(bx["b"][1] // bucket), int(bx["b"][3] // bucket) + 1):
  89|                 self.idx[k].append(bx)
  90| 
  91|     def at(self, bbox, thr=0.25):
  92|         seen, best, bt = set(), 0.0, None
  93|         for k in range(int(bbox[1] // self.bucket), int(bbox[3] // self.bucket) + 1):
  94|             for bx in self.idx.get(k, ()):
  95|                 if id(bx) in seen:
  96|                     continue
  97|                 seen.add(id(bx))
  98|                 v = iou(bbox, bx["b"])
  99|                 if v > best:
 100|                     best, bt = v, bx
 101|         if bt is None or best <= thr:
 102|             return None, None

 104|         # A line box holds several words; a single-word query wants the word, and
 105|         # returning the whole line would manufacture disagreement at every token.

## `artifacts/ARTIFACTS.md`  (144 lines)

   1| # What actually goes wrong in a scanned document
   2| 
   3| This is the defect catalogue this tool was built against. Every class below was
   4| observed in the five documents in [`../samples/`](../samples/), with counts from the
   5| 41-page EOIR Cumulative Index (29,853 words, four engines).
   6| 
   7| The last section is the important one: **the defects this tool does not catch.**
   8| 
   9| ---
  10| 
  11| ## A. Defects a quorum fixes
  12| 
  13| ### A1. The separator disappears — `12-855` becomes `12855`
  14| The most common failure in this corpus and the most expensive. A volume–page citation
  15| loses its hyphen and becomes an unsearchable seven-digit number. Engines disagree about
  16| which of `‐ ‑ ‒ – — ― −` they saw, or whether they saw one at all.
  17| 
  18| **Why it costs so much:** searching the document for `12-855` returns nothing, and
  19| returns it with no indication that anything is wrong. Measured: the existing text layer
  20| of the index contained **2,583** citations of this shape; the quorum recovered **3,182**,
  21| and **1,825 distinct** citations against **1,629**.
  22| 
  23| **Fixed by:** the `SEP` rule — when the digits agree and only the separator differs, take
  24| the cleanest form.
  25| 
  26| ### A2. Two citations weld together — `8409;11-224;`
  27| Adjacent citations run into one token, so both become unsearchable at once. Detected by
  28| comparing digit runs across engines.
  29| 
  30| ### A3. Letters read as digits and back — `l`/`1`, `O`/`0`, `S`/`5`, `B`/`8`, `i`/`1`
  31| `lOl(b)(l)(B)` for `101(b)(1)(B)`. In a statute subsection this is not cosmetic.
  32| **Fixed by:** the `NUM` rule — fold the confusable pairs, and if agreement appears, keep
  33| the candidate that needed the fewest substitutions.
  34| 
  35| ### A4. Stray punctuation — `May 1, .1974`
  36| Harmless to a reader, fatal to an exact-match quotation check, which is what a citation
  37| verifier does. **Fixed by:** the vote, on the normalised form.
  38| 
  39| ### A5. Hyphenation debris — `los` where the page reads `loss`
  40| A word broken across a line break leaves a fragment that looks like a real short word.
  41| **Fixed by:** the `LEX` rule, weighted by how often the document itself uses each form —
  42| and deliberately never applied to a capitalised token, because that is where surnames and
  43| case names live and a dictionary would "correct" them into different people.
  44| 
  45| ---
  46| 
  47| ## B. Defects a quorum does **not** fix — read this part
  48| 
  49| ### B1. 🔴 Truncation. All engines agree, and all are wrong.
  50| **This is the one that matters.**
  51| 
  52| The engines are given the same region of the page to read. If that region is cut short —
  53| a box ending mid-word — then every engine reads inside the same wrong box, and they agree
  54| unanimously on a fragment. Four voices, perfect consensus, wrong answer.
  55| 
  56| Measured on this corpus: **289 truncations in 91,879 tokens (0.31 %)** across the working
  57| set, found by an independent fifth engine reading with its own layout analysis and
  58| checking whether our token was a proper substring of what it read at overlapping
  59| coordinates.
  60| 
  61| The number that should worry you is this one: of 24 disagreements checked by eye,
  62| ScanQuorum was right on 17 and **wrong on 7 — and all 7 were truncations.** So this class
  63| is not merely uncaught by the vote; it is *the majority of what is left*.
  64| 
  65| 🔴 **And the accuracy measurement cannot see it, by construction.** The reference standard
  66| was built by rendering each token's box at 900 dpi and reading it. If the box is wrong,
  67| the reference is wrong in exactly the same way. A crop-relative gold standard can never
  68| find a truncation. This is a hole in the measurement, not just in the tool, and no amount
  69| of additional sampling closes it.
  70| 
  71| **Partial defence, shipped:** `--detect-truncation` runs a second engine with independent
  72| layout analysis and flags any token that is a proper substring of what that engine read at
  73| overlapping coordinates. It is a detector, not a fix.
  74| 
  75| ### B2. Words no OCR engine ever sees
  76| **340 words** in the index were present in the original text layer and read by none of the
  77| neural engines — most of them in the running heads, margins and column gutters that layout
  78| analysis discards. They are kept, credited to the single engine that saw them, and marked
  79| as unconfirmed rather than dropped.
  80| 
  81| The inverse also happens: text the old layer never had, which the new engines find. Both
  82| directions matter, and a tool that only ever *replaces* a layer silently loses the first
  83| kind.
  84| 
  85| ### B3. Correlated engines
  86| Two of the four default engines share a text detector: **2,921 of 3,006 boxes are
  87| byte-identical**. When those two agree, that is close to one opinion, not two. A "3 of 4"
  88| majority containing both of them is weaker than a "2 of 4" majority that does not.
  89| 
  90| This is why the fourth engine was added. It is the weakest of the four and it still helped
  91| — because it is the only one that draws its own boxes. **Independence beats accuracy in an
  92| ensemble**, and adding a fifth engine from the same family would add nothing.
  93| 
  94| ### B4. The right word in the wrong place
  95| Nothing here checks reading order. A word correctly recognised but placed in the wrong
  96| column produces a quotation that is verbatim and meaningless. Two-column detection is
  97| heuristic (a whitespace gutter); it is right on this corpus and is not guaranteed anywhere
  98| else.
  99| 
 100| ---
 101| 
 102| ## C. Defects in the tool itself, found and fixed
 103| 
 104| Kept here because a catalogue of other people's failures and none of your own is marketing.
 105| 
 106| ### C1. Token duplication — 1.29× inflation
 107| Overlapping OCR line boxes each claimed the same word, so a word appeared in the output
 108| once per box that covered it. In assembled text this read `On On On November November
 109| November`. On full-width pages it inflated the text by **1.29×**; on the narrow-column
 110| index it was almost invisible (7 cases in 29,858), which is why it survived two rounds of
 111| code review.
 112| 
 113| It died the first time someone *used* the tool to pull a quotation. **Reading code did not
 114| find it; applying the artefact did.**
 115| 
 116| ### C2. 🔴 Ties broken by dict ordering — found while publishing this repository
 117| Four separate places in the decision cascade resolved a tie with
 118| `Counter.most_common()` or `max()`, both of which return whichever item the dictionary
 119| happened to yield first. **165 of 11,780 distinct decisions (1.40 %) changed their answer
 120| when the engines were reordered. 29 of those changed a digit:**
 121| 
 122| ```
 123| 12-869  vs  12369      a different citation
 124| 1910    vs  1940       a year, thirty years apart
 125| 11-335  vs  11-336     adjacent citations, both plausible
 126| ```
 127| 
 128| The defect had already been found once, for the 2:2 vote split, and fixed there with the
 129| note that insertion order decides *"silently, and by an accident of dict ordering."* It
 130| was fixed in one place out of four. Three of the remaining sites were found by a parity
 131| test written for a completely different purpose; the fourth was only exposed after the
 132| first three were fixed.
 133| 
 134| **Now:** ties that are merely about punctuation are settled by a stated rule (fewest stray
 135| marks, then shortest, then lexicographic); ties that hold different digits are sent to the
 136| reader as disputes. 33 decisions moved from "guessed" to "shown to you". No gold-set crop
 137| changed, so the published accuracy still describes the current code.
 138| 
 139| ### C3. A tie-break fix that was itself wrong
 140| The first version of that fix ignored how many engines backed each form, so with
 141| `children;` from three engines and `children:` from one it returned the single engine's
 142| reading, because `:` sorts before `;`. The parity test caught it on its first run.
 143| 
 144| **Three engines agreeing is not a tie.** Count first; break only the tie that is there.
```
